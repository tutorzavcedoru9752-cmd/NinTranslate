# NinTranslate 1.6.2 截图响应优化验收

验收日期：2026-10-15。当前为本地测试版本。

## 原因与修改

原版的快捷键处理会先通过 `desktopCapturer.getSources` 获取所有屏幕，再把全屏画面逐个压缩为 PNG、编码为 base64，随后逐个创建 Electron 窗口并加载 React 页面。取消或完成截图会销毁所有截图窗口。多屏、高分辨率环境会重复承担这些成本。OCR 模型不在快捷键唤起路径中，这次延迟与多语言模型无直接关系。

1. 应用启动时提前加载截图窗口，平时隐藏。取消、完成截图时隐藏并清除画面，不再销毁窗口。
2. Windows 随包提供一个使用系统 .NET Framework 与 Win32 GDI 的常驻小组件。只在触发时采集，原始像素通过标准管道送入主进程，不落盘、不持续录屏。
3. 全屏画面使用无损 BMP，经随机、一次会话有效的 `nin-capture://` 内存地址传输，响应包含 `Cache-Control: no-store`；避免全屏 PNG 压缩和 base64。用户选区仍延续原来的裁剪、放大和灰度增强，再把选区 PNG 送入本地 OCR。
4. 多屏窗口并行加载、并行准备画面，全部加载成功后显示。鼠标所在屏幕获得键盘焦点。
5. 重复按快捷键不会并发创建选区层，也不会把选区层当作桌面再次截图；旧会话通知和裁剪结果会被忽略。
6. Windows 截图窗口禁用系统淡入淡出，读取画面前同步桌面合成，避免快速重截图捕获上一层动画残影。
7. 隐藏窗口不等待 `requestAnimationFrame` 或 `Image.decode()`；改为实际显示图片的加载事件通知就绪，避免隐藏窗口被浏览器节流，以及预加载图片和显示图片重复加载造成首帧空白。
8. 原生组件失败自动退回 Electron；屏幕插拔或缩放变化时更新窗口。补充右键取消、窄窗口提示排版与减少动态效果适配。

## 性能数据

在同一台 Windows 10 x64 电脑、同版本 Electron 37.10.3、两个显示器上测量。系统报告的缩放约为 192.5% 和 137.5%，逻辑尺寸分别为 1995×1123 和 1397×786。保留原始屏幕分辨率，没有通过缩小截图提速。

| 指标 | 原版路径，8 次 | 优化路径，20 次 |
|---|---:|---:|
| 响应中位数 | 2911 ms | 255 ms |
| 样本 P95 | 3465 ms | 285 ms |
| 首次样本 | 3465 ms | 361 ms |

中位数延迟降低约 91.2%，约为原来的 1/11.4。原版单次全屏 PNG 编码约 1541–1587 ms；优化版不再进行这一步。

测量起点为调用截图控制器，终点为屏幕画面加载完成、原生窗口显示调用完成。优化测试包含第一次采集样本，但应用启动时的窗口预热在采样前完成。这不是外置高速摄影测量的键盘硬件到显示器像素延迟。原版基准保留原有串行创建窗口/PNG 编码路径。

原始数值保存在 `output/capture-baseline.json` 和 `output/capture-optimized.json`。运行 `npm run test:capture` 可在本机复测当前路径；测试画面仅存于内存，报告只保存数值。基准期间会短暂显示选区层。

- 类型检查与生产构建通过。
- 13 个单元测试文件、64 项测试通过，包括窗口复用、重复触发、取消中的请求、会话校验、显示器变化、失败重试、位图像素一致性。
- 17 项实际本地 OCR 夹具测试通过，覆盖十语种、用户提供的多行和分段样本。
- 真实 Electron/Windows 集成验收通过 9 项：物理像素和缩放坐标；真实操作系统快捷键；双屏置顶；Esc 取消与清理；新画面标记；鼠标框选/Canvas 权限；框选后中英文 RapidOCR；原生组件丢失自动回退；桌面与 360 px 窄窗口及控制台。
- 实际视觉截图检查通过，合成中英文测试内容可见，提示文字没有裁切或横向溢出。截图在 `output/playwright/capture/`。
- Windows 安装版和便携版正式构建成功，二者产品版本均为 `1.6.2`。安装版为 278,760,144 字节，比本地 `1.6.1` 安装版增加 6,619 字节；便携版为 278,387,440 字节，增加 6,612 字节。
- 打包后的 `app.asar` 已确认包含截图控制器、位图传输模块与就绪 IPC。`resources/capture/win32-x64/screen-capture.exe` 为 6,656 字节。
- 使用打包后的 `app.asar` 页面、preload、主进程模块、原生采集组件和 OCR 运行时，再次完成上述 9 项真实交互验收，0 控制台错误。使用隔离数据目录，没有退出正在运行的旧版，也没有修改其设置或历史。
- Web UI 静态检查：0 错误、1 警告。警告为项目原有 `styles.css` 中存在颜色字面量；本次截图层新增/修改样式使用语义变量，并复用原有配色和字体。

真实交互验收命令：`npm run test:capture:ui`。它会创建专用测试窗口、临时注册 `Control+Alt+Shift+F10` 并通过系统键盘事件触发，完成后清理临时快捷键与窗口。它不会修改用户自己的截图快捷键。

打包资源验收命令：`node scripts/verify-capture.cjs packaged`，需要先运行 `npm run dist:win`。

交付位于项目 `outputs/v1.6.2/`：Windows 安装版、便携版、源代码 ZIP、使用说明、验收报告、原始性能数据和测试窗口截图。未执行 GitHub 推送、标签或 Release 操作。

接口参考：[Electron desktopCapturer](https://www.electronjs.org/docs/latest/api/desktop-capturer)、[Electron BrowserWindow](https://www.electronjs.org/docs/latest/api/browser-window)。

## 限制

- 尚未在真实 Mac 上测量；Mac 使用原来的系统采集接口，但共享窗口预热与 BMP 传输优化。未进行远程 Mac 构建或发布。
- 未在同一环境测量微信和 Snipaste，不能声称所有设备上的响应时间与它们完全一致。当前双屏实测约四分之一秒，与原版数秒等待相比显著缩短；仍存在原生画面跨进程传输和 Chromium 绘制成本。
- 未执行新系统安装、卸载和所有显示器/显卡组合验收；当前实机验证的是上述双屏非整数缩放配置。
- 翻译服务的真实联网请求耗时不属于此次快捷键唤起优化范围。
- 窗口预热会保留少量额外内存；没有后台连续截图。取消/完成后释放主进程截图引用、使内存地址失效并清除界面图片引用，内存最终由系统回收。
